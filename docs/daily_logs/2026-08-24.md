## 2. Design frontend

Nouvelle page publique `verification-certificat/:reference` (aucune garde de
route, comme `accueil` ou `contact`), avec logotype identique au reste de la
plateforme (`INPG` + `LMS` en `text-brand`, CLAUDE.md §1). Trois états — chargement,
authentique, introuvable — dans une carte `bg-surface-container-lowest` avec
`shadow-sm` et bordure `outline-variant`, en respectant le piège
`font-<échelle>`/`text-<échelle>` (toujours les deux classes) et le piège des
jetons jumeaux (`on-error-container` sur `error-container`, jamais
`primary-fixed` sur `primary-container`). Pas de nouveau jeton inventé : tout vient
de `tailwind.config.js` (dont les jetons `success`/`error`/`error-container`
déjà présents).

## 3. Implémentation

**Backend**

  comme les autres méthodes du repository).

  libre. Nouvelle propriété `app.frontend.base-url` (par défaut
  `http://localhost:4200`, surchargeable via `APP_FRONTEND_BASE_URL`).

**Frontend**
- `features/verification-certificat/` : modèle, service HTTP (sans en-tête
  d'authentification requis), composant standalone + route publique dans

## 6. Points de sécurité vérifiés

- Entrée validée côté serveur avant toute requête base : la référence doit
  correspondre au format figé par `Certificat#genererReferenceSiAbsente`
  (`INPG-CERT-AAAA-XXXXXXXX`), sinon 404 immédiat sans toucher au repository
  (test dédié : `une_reference_malformee_renvoie_404_sans_interroger_la_base`).
- Contrôle d'accès : endpoint volontairement public (`GET` uniquement,
  `permitAll` restreint à ce préfixe dans `SecurityConfig`), documenté en
  Javadoc — ce n'est pas un oubli de `@PreAuthorize`. `EspaceEtudiantGardeFousTest`
  ne s'applique pas (il ne scanne que `EspaceEtudiantController`), et c'est
  volontaire puisque ce contrôleur est un autre fichier.
- Réponse publique minimisée : `CertificatVerificationDto` ne renvoie ni
  identifiant technique, ni matricule, ni aucune donnée de compte (email,
  téléphone) — seules les informations nécessaires à confirmer l'authenticité
  d'un diplôme.
- Pas d'injection : accès base via repository Spring Data / `@EntityGraph`,
  aucune requête construite par concaténation.
- Pas de secret ni de token loggué ou renvoyé dans une réponse JSON — vérifié par
  relecture des fichiers modifiés/ajoutés.
- Vigilance restante, non bloquante : la référence sert de facto de jeton
  d'accès (8 caractères hexadécimaux aléatoires + année, soit ~4,3 milliards de
  combinaisons par an) ; aucune limitation de débit n'a été ajoutée sur cet
  endpoint public. Risque jugé faible (pas d'énumération utile — un succès ne
  renvoie que des informations déjà imprimées sur un document physique) mais à
  surveiller si l'endpoint est un jour exposé à un trafic non fiable élevé.
