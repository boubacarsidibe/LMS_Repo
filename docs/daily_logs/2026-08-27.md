## ~09:10 UTC — demande directe : design de la page d'inscription

L'utilisateur a signalé que le formulaire d'inscription affiche "Prénom"/
"Nom" pour les comptes École et Entreprise, ce qui n'a pas de sens pour
une organisation. Priorité immédiate sur le travail de routine, conforme
au fonctionnement établi de cette session.

Vérifié dans le code (`UserDto`, `UserService.createUser`,
`CrudControlleur.registerUser`) : ces deux champs ne sont **jamais
persistés séparément** sur `User`, ils ne servaient qu'à composer un
`username` côté client (`prenom_nom`). Le vrai nom de l'organisation
(`raisonSociale` pour `Entreprise`, `nomEcole` pour `EcoleFormation`)
n'est de toute façon recueilli qu'à la soumission de la demande réelle
(`EntrepriseController`, `EcoleAccreditationController`) — aucun
changement backend nécessaire.

Correctif (branche `agent/dev-autonome-inscription-design`, PR #86) :
- Candidat(e) : conserve Prénom/Nom.
- École / Entreprise : un unique champ "Nom de l'école"/"Nom de
  l'entreprise" (libellé dynamique), avec note indiquant que description/
  secteur/adresse seront demandés à l'étape suivante.
- Validators Angular ajustés dynamiquement selon le type de compte.
- `username` généré à partir du nom d'organisation (slugifié) plutôt que
  prénom/nom pour ces deux cas.
- Polish visuel demandé au passage : cartes de type de compte empilées
  sur mobile (`grid-cols-1 sm:grid-cols-3`) au lieu de 3 colonnes
  compressées ; état sélectionné plus lisible (fond plein
  `bg-secondary-container`/`text-on-secondary-container`, paire de jetons
  vérifiée non-jumelle dans `tailwind.config.js`) au lieu d'un survol à
  20% d'opacité à peine visible.

Vérifié : `npx tsc --noEmit -p tsconfig.app.json` sans erreur, `ng build
--configuration development` réussi avec les nouvelles classes présentes
dans le bundle compilé. Pas de navigateur dans ce sandbox — vérification
par lecture de code et build réel, pas par capture d'écran en conditions
réelles.
